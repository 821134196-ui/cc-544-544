# 当面验货托管交易平台

买卖双方约定当面验货后，平台生成交易单与托管金额；卖家交付时填写序列号、外观、
配件，买家在约定窗口内验收；双方确认一致后才释放款项，争议期间资金保持冻结。

仅依赖 Python 3 标准库（`sqlite3` + `wsgiref` + `unittest`），无需安装任何依赖。

## 快速开始

```bash
python3 run.py                 # 初始化数据库 + 生成样例 + 启动服务
# 打开 http://127.0.0.1:8000/  （默认视角：买家小陈，页面右上角可切换角色）
```

其他命令：

```bash
python3 run.py --seed-only     # 只生成样例数据
python3 run.py --port 9000     # 指定端口
python3 -m unittest discover -s tests -v   # 运行测试（30 个用例）
```

## 状态机

```
AGREED ──pay──▶ FUNDING ──回执──▶ ESCROWED ──deliver──▶ INSPECTING ──双方确认──▶ COMPLETED(放款)
                   │                  │                    │
                超时扫描            cancel              reject/申诉
                   ▼                  ▼                    ▼
           PAYMENT_DELAYED      CANCELLED(退款)        DISPUTED ──指派──▶ ARBITRATING ──裁决──▶ COMPLETED / REFUNDED
```

六类异常均有状态或争议原因：物品与描述不符、买家逾期不到、卖家撤销、
付款回执延迟、验货后发现隐藏故障、双方各自提交相反结论（自动升级标记）。

## 资金安全设计

- **托管流水**（`ledger_events`）：`HOLD`（买家→托管）、`RELEASE`（托管→卖家）、
  `REFUND`（托管→买家）三种事件，所有资金变动只经由此表。
- **资金守恒**：每笔交易 `冻结 = HOLD − RELEASE − REFUND ≥ 0`，全局
  `ΣHOLD = ΣRELEASE + ΣREFUND + Σ冻结`；首页与启动时均展示校验结果。
- **互斥**：付款、退款与放款互斥——服务层状态机检查 + 数据库部分唯一索引
  （每单至多一条 HOLD/RELEASE/REFUND）+ 触发器（放款后禁退款、退款后禁放款、
  结算后禁再托管）三重保证。
- **回执幂等**：回执号唯一索引，重复回执直接忽略，不会形成第二笔资金流；
  回执金额与托管金额不一致时拒绝入账；回执迟到但交易已取消时，先入托管再
  自动原路退回，保持守恒。

## 权限隔离

- **验货人不能直接修改托管金额**：仅平台可在付款前调整，付款后金额锁定。
- **仲裁员不得处理自己参与的交易**：指派时校验其不是该交易的买家/卖家/验货人；
  只有被指派的仲裁员可以裁决。
- 确认、付款、交付、申诉等操作均校验操作者身份；证据仅交易参与者（含验货人）可提交。

## 界面

- **交易页**：顶部固定栏显示托管金额、剩余验货时间（秒级倒计时）、双方确认状态与当前状态。
- **争议页**：商品描述（含上架图与卖家交付清单）与现场照片并排展示，
  下方为双方证据与结论、仲裁指派与裁决。
- 色彩仅使用白、深灰与有限的绿色结论提示（确认、裁决、守恒校验通过）。

## 目录结构

```
escrow/
  domain.py    状态机、争议原因、业务异常
  db.py        SQLite schema（唯一索引 + 触发器兜底）与事务
  ledger.py    托管流水入账与资金守恒校验
  payments.py  模拟支付渠道适配器（回执可延迟、重放安全）
  service.py   业务编排：约定/托管/验货/争议/仲裁/放款
  photos.py    虚构 SVG 照片生成
  web.py       WSGI 界面
seed.py        样例数据（拒收、延期、回执延迟等八笔）
run.py         一键启动
tests/         30 个测试：资金守恒、回执重放、验货时限、权限隔离等
data/          运行时生成的 SQLite 库与照片（不入库）
```
